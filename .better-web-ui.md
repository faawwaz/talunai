### Design Principles

1. Put the next task ahead of generic metrics; express priority through spacing and weight before color.
2. Separate application workflow, funding, invoice collection and withdrawals. Pending transaction never means success.
3. All operational data comes from authorized backend endpoints. Read-only synthetic previews must be visibly marked and must never grant roles.
4. Present exact amounts, fee, recipients, network and action before signatures; preserve inputs through recoverable errors.
5. Provide keyboard focus, mobile layouts, honest empty/error/pending states, and reduced motion. Keep testnet/simulation visible without overwhelming the task.

Context is taken from the user's supplied design brief; no additional aesthetic choice is pending.
